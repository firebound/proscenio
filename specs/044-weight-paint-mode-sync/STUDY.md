# Spec 044: Weight Paint mode sync and bind parameters

Make Proscenio's Edit Weights track Blender's weight-paint mode, surface the bind parameters that today hide in the redo panel, tame the per-bone override list, and add a clear-empty-vertex-groups shortcut.

## Scope

- **Sync Edit Weights to the weight-paint mode.** Two symptoms, one cause - the provenance overlay does not track the mode. (a) Painted vertices only turn white after leaving and re-entering the mode: the overlay is not refreshed after a stroke. (b) Leaving the mode via Blender's native controls does not end Proscenio's Edit Weights modal, so the overlay flag and marks persist. The "Edit Weights" button should also read "Exit Painting Mode" while in the mode - same `context.active_object.mode` check as the sync work, so they are one unit.
- **Expose the Proximity bind parameters.** `max_distance` and `falloff_power` are reachable only through the F9 redo panel; draw them in the Bind subpanel, shown only when the mode is Proximity.
- **Bound the per-bone override list.** It renders every bone as a row with no scroll, pushing the rest of the Bind subpanel down. Reuse the reusable list component built in spec 046 (which must land first), or fall back to a search/collapse treatment.
- **Clear empty vertex groups.** A shortcut that drops every vertex group with no nonzero weight, behind a confirm that lists what will be deleted.

Out of scope / a larger follow-on: named weight snapshots (a new save-point data structure with explicit "return to before / after paint" choice and its file I/O). Kept as a deferred note below.

## Study

### Surface notes

**The live-refresh symptom is an architectural limit, not a missing redraw call.** The modal at `operators/skinning/edit_weights.py:110-131` is a passive observer: it `PASS_THROUGH`s every event and the provenance flip (`StrokeDiffTracker.flip_touched_after_stroke`, `core/bpy_helpers/skinning/stroke_diff.py:39-79`) runs only on `LEFTMOUSE`/`RELEASE` (modal:117-121), `WINDOW_DEACTIVATE` (:122-124), and the zero-pressure `MOUSEMOVE` heuristic (:125-127). The diff is computed by reading the whole active vertex group's weights before and after the stroke - it has no per-sample hook, because Blender's brush stroke is a native operator Proscenio only brackets. So "live during the stroke" is genuinely **not supported by this architecture**: the sidecar provenance for a vertex cannot flip to `user_paint` until the stroke is complete and the before/after diff exists. The achievable, honest target is **refresh at stroke end**: the flip already happens there, and the modal already calls `context.area.tag_redraw()` after a touched RELEASE (:119-120). What is missing is that the overlay's GPU batch is rebuilt from the sidecar on every draw anyway - `weight_overlay._draw_callback` (`core/bpy_helpers/skinning/weight_overlay.py:91-108`) re-reads the sidecar copy-property and rebuilds the POINTS batch each invocation via `_read_provenance_entries` (:50-67) + `_draw_color_groups` (:70-88). There is no stale cached batch. That means the tag_redraw on RELEASE *should* already repaint the touched verts white; the reported "only after re-entering the mode" suggests the redraw tag is not reliably reaching the VIEW_3D window region during a brush stroke pass-through (a single `context.area.tag_redraw()` tags only the active area, and a weight-paint stroke can leave the cursor over a different region at release). The fix shape is to tag a redraw on all VIEW_3D areas at stroke end (the codebase already has the `_tag_redraw_view3d` idiom in `operators/automesh/automesh_authoring.py:320`), and to also flip+redraw on the `WINDOW_DEACTIVATE` and zero-pressure paths that today flip but do not tag. No new per-sample machinery; the ceiling stays "white at stroke end," and the scope line must say so.

**The external-exit symptom needs the modal to watch its own mode, not a depsgraph callback.** When the user leaves weight-paint mode through Blender's own header dropdown, tab, or pie menu, no event is delivered to Proscenio's modal - it keeps `PASS_THROUGH`ing, `_finish` (`edit_weights.py:133-144`) never runs, and so `unregister_handler`, `_remove_statusbar`, and `restore_session` never fire. The overlay handler stays registered and the `show_provenance_overlay` flag stays True (`_restore_overlay_flag`, `core/bpy_helpers/skinning/modal_session.py:81-85` is part of `restore`, :58-78, which only runs from `_finish`). The tempting fix - have the depsgraph handler in `properties/_handlers.py` call `_finish` - is unsafe: depsgraph callbacks run in a restricted context where `bpy.ops.object.mode_set` and `bpy.ops.ed.undo_push` (`_finish:135-136`) may not be callable and can corrupt the depsgraph, and `_finish` also mutates selection and the active object. The safe detection path is that **the modal is already running while in the mode**, so it can poll `context.active_object.mode` itself. The clean idiom is an `event_timer_add` poll exactly like the automesh authoring modal (`operators/automesh/automesh_authoring.py:316-318` adds the timer, :348-349 dispatches `event.type == "TIMER"`): on each TIMER tick, if the active object's mode is no longer `WEIGHT_PAINT`, the modal calls `self._finish(context, cancel=False)` from inside its own `modal()` - the one context where `_finish`'s operator calls are legal. A timer is needed (not just MOUSEMOVE) because a native mode exit may deliver no further mouse events to the modal. The timer must be removed in `_finish` alongside the overlay handle. This is the same `context.active_object.mode` check the button-label item needs, so the two ship together.

**The button label is a panel-side mirror of the same mode check.** `_draw_edit_weights` (`panels/weight_paint.py:246-280`) draws the entry button with the static text `"Edit Weights"` (:265-269). While the active object is in `WEIGHT_PAINT` mode the label should read "Exit Painting Mode" and the button should end the modal rather than re-enter it. The panel already has `context.active_object` in scope via the caller (`PROSCENIO_PT_edit_weights.draw`, :99-101). The shape: branch on `obj.mode == "WEIGHT_PAINT"` for the button text and icon; the exit click can simply set Object mode (the modal's own TIMER poll then runs `_finish`), which keeps a single exit code path instead of duplicating teardown in the panel. Grouping with the sync work avoids two reads of the same predicate drifting apart.

**The Proximity parameters are a layout-only gap - the plumbing already exists end to end.** `_draw_bind` (`panels/weight_paint.py:158-190`) draws only `bind_init_mode` (:174) and the target line; it never draws the falloff/distance props. The scene props exist (`properties/scene_props.py:257` `bind_falloff_power`, :268 `bind_max_distance`), the operator declares matching props (`operators/skinning/bind_mesh.py:80-94`), invoke seeds them from the scene props (:106-109), and `apply_bind` is called with both (:138-143). So the entire data path is live; only the panel draw is absent. The fix is to draw `bind_falloff_power` and `bind_max_distance` in `_draw_bind`, guarded by `bind_mode == "PROXIMITY"` (`_draw_bind` already reads `bind_mode` into a local at :172-175 for the override box, so the guard is free). The other four modes ignore both params (Envelope reads a per-bone radius custom property, Single-nearest/Empty/Bone-heat take neither), so drawing them under any non-Proximity mode would be inert UI - the conditional is correct, not just tidy. This directly fixes the `BL-WPAINT-SWEEP` note "o painel do weight paint mode não tem as duas opções de max_distance e falloff_power que aparecem no painel de redo".

**The override list has no scroll because it is a hand-rolled row-per-bone loop.** `_draw_bone_overrides` (`panels/weight_paint.py:193-243`) iterates `picker.data.bones` and draws a `box.row()` per bone with Soft/Hard/Clear buttons (:221-243). A box grows to fit its contents - there is no native scrollbar for `UILayout.box()` children - so a picker with many bones pushes Bind, then the whole Weight Paint panel, far down. The right answer is a native `UIList`, which scrolls and searches for free; but Proscenio has no shared list helper today (`panels/_helpers.py` holds only header utilities, per spec 046's surface notes). Spec 046 is building exactly that reusable list component (its scope line names "the Weight Paint override list (spec 044)" as an adopter). So this item **depends on spec 046 landing first** and then adopts the component - it should not hand-roll a second UIList here. The interim fallback, if 046 slips, is a collapsible "active overrides only" view (draw only bones that already carry a Soft/Hard override, since `read_bone_modes` is already consulted at :220) plus a count, which bounds the height without a new widget. The list migration also has to preserve the per-row depress state and the Clear-enable predicate the existing rows encode.

**Clear-empty-vertex-groups is a new operator plus a confirm dialog.** No such operator exists today (the only "empty vertex group" references in the tree are doc prose and a validation-export test fixture). The mesh's vertex groups are at `obj.vertex_groups`; "empty" means a group no vertex weights above zero - the same predicate `stroke_diff._read_group_weights` (`core/bpy_helpers/skinning/stroke_diff.py:87-95`) already uses (weight > 0). The operator should collect the empty groups, present a confirm (Blender's `invoke_confirm` / a `draw`-based popup) listing the group names that will be deleted, and only then remove them. Two cautions specific to this codebase: the bind sidecar carries `vertex_group_names` (`stroke_diff.py:72`), so deleting groups can desync the sidecar/topology relationship the modal's preconditions check (`edit_weights._validate_invoke_preconditions:182-187`) - the confirm copy or a follow-up should note that empty groups are safe to drop precisely because they hold no weights, but a bound mesh's base groups should be inspected before mass deletion. Surfacing it as a Bind- or Snapshot-subpanel button (not a bare shortcut) keeps it discoverable and lets the poll require a mesh element.

### Research notes

- **Detecting a Blender mode change.** Blender offers three native mechanisms: `bpy.app.handlers.depsgraph_update_post` (fires on data changes, restricted context - unsafe for calling operators), `bpy.msgbus` RNA subscriptions (`bpy.msgbus.subscribe_rna` on `Object.mode`, fires a callback on the property change but the callback runs in the same restricted-ish context and needs a `persistent` owner across undo), and a modal `event_timer_add` poll. Proscenio already runs a modal while in the mode, so the timer poll is both the simplest and the only one whose callback executes in a context where `mode_set` / `undo_push` are legal - it reuses the exact pattern in `operators/automesh/automesh_authoring.py:316-349`. msgbus would be the right tool for a *non-modal* watcher; here the modal already exists, so adding a watcher would duplicate state.
- **Why "live" weight overlay is hard upstream too.** Blender's own weight-paint display updates the mesh color attribute as a native brush operation; an addon bracketing that operation (as Proscenio does) sees only stroke boundaries, not per-dab callbacks - there is no public per-sample paint hook. This is why the honest ceiling is stroke-end refresh, and it matches how Blender's own custom paint addons behave.

### Verdict summary

**Four now, one gates on spec 046, one defers.** The work groups into **three PR-sized chunks**. PR 1 is the mode-sync unit: the external-exit TIMER poll that calls `_finish` from inside `modal()`, the stroke-end redraw-all-VIEW_3D-areas fix on every flip path, and the "Exit Painting Mode" button label - one unit because all three turn on `context.active_object.mode` and share the single `_finish` exit path; verified by a GUI smoke pass over `BL-WPAINT-EDIT-01`/`EDIT-02` plus a headless test that asserts the TIMER tick ends the modal when mode flips. PR 2 is the Proximity-params panel draw (headless panel-shape test, plus the `BL-WPAINT-SWEEP` visual row) and the clear-empty-vgroups operator with its confirm (headless operator test on a fixture with one weighted and one empty group). PR 3 is the override-list migration, sequenced after spec 046's reusable list component lands; it adopts the component, preserves the depress/Clear-enable encoding, and is verified against `BL-WPAINT-BIND-02`. The honest limit to carry into the scope note and the docs: the provenance overlay refreshes at **stroke end**, not live during a stroke - the architecture brackets a native brush operator and has no per-sample hook.
