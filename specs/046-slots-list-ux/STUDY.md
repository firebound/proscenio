# Spec 046: Slots list and attachment UX

Bring the slot lists to a native, searchable widget, make attaching to an existing slot possible without juggling selection, and factor out the reusable native-list component the other panels adopt.

## Scope

- **Factor out a reusable native-list component** in `panels/_helpers.py` that wraps `template_list` with identity-based active-index sync, so the Slots panel, the Weight Paint override list (spec 044), and any later list share one shape — and so the active-index bug the Skeleton panel already paid for is fixed once, by construction, not per panel.
- **Expose a selection mode (single vs multi) on the component.** A list opts into Shift/Ctrl multi-selection only where it maps to a real selection. This is decided, not open: multi for the lists that back onto Blender's own selection (Outliner objects via `obj.select_set`, Skeleton bones via `bone.select`) and the Weight Paint per-bone overrides (to batch-set the mode); single for the lists that are a one-of pick (Animation action assignment, the active slot, a slot's default attachment). Because `template_list` carries a single `active_index`, multi needs a per-item selected state and a custom per-row marker — the multi-highlight is a custom approximation, not native (Blender's own UILists are single-active; only the Outliner *editor*, which is not a UIList, is multi). This is also what answers the Outliner Shift-select request: it becomes a capability of this component, turned on per list.
- **Migrate the project slot list** (`panels/slots.py:117-128`) from its hand-rolled per-row column to the shared component, backed by the existing scene objects collection with a slot-only filter.
- **Migrate the active-slot attachment list** (`panels/slots.py:186-205`) — the structurally hard one, because it is drawn over `empty.children` filtered at draw time, which is not a `bpy` `CollectionProperty` a `template_list` can bind to. Decide and implement the backing (a synced `CollectionProperty` vs a custom-draw list inside the shared component).
- **Add an attach-to-existing-slot mesh picker** so a mesh can be attached without first selecting it then re-activating the slot, which single-object selection makes impossible. The bone half is already covered (the Bind to Bone dialog) — confirmed below; this row is mesh-only.
- **Remove the redundant empty-slot warning** — the panel and the validator both announce an empty slot; keep one.

## Study

### Surface notes

**Two hand-rolled lists, two different shapes.** `panels/slots.py` draws both lists as plain `column`/`row` loops, not `template_list`. The project list (`slots.py:113-128`) builds `slots = sorted((o for o in context.scene.objects if _is_slot(o)), ...)` and emits one `row` per slot: a `proscenio.select_slot` operator button (`depress=slot is active`) carrying `slot_name`, plus a child-count label. The attachment list (`slots.py:166-205`) sorts `empty.children` filtered to `type == "MESH"` and emits per child a `set_slot_default` toggle (`SOLO_ON`/`SOLO_OFF`), the name, a kind label/icon, and a `keyframe_slot_attachment` button. Neither has search, neither scrolls, and the attachment list grows the panel unboundedly — the same unbounded-growth complaint spec 044 logs for the Weight Paint override list, which is the reuse case this component exists to serve.

**How the existing `template_list`s bind — three working precedents.** All three current lists bind a `template_list` to a real `bpy` collection plus a scene-prop active index:

- Outliner (`outliner.py:150-158`) binds `bpy.data, "objects"` with `scene_props, "active_outliner_index"`, and does all its slot/attachment/element/armature shaping inside `PROSCENIO_UL_sprite_outliner.filter_items` (`outliner.py:86-124`) — it hides non-Proscenio objects with `bitflag_filter_item` and reorders by category rank via `flt_neworder`. This is the proof that a `template_list` can present a *slot-only filtered* view of `bpy.data.objects` without a dedicated collection: the slot list's filter is a strict subset of what the Outliner already does.
- Skeleton (`skeleton.py:150-158`) binds `target.data, "bones"` with `active_bone_index` — a real native collection (`Armature.bones`).
- Animation (`animation.py:59-67`) binds `bpy.data, "actions"` with `active_action_index` — again a native collection.

The active indices are plain `IntProperty(min=0)` on the scene (`scene_props.py:435-446, 484-489`), and selection writes them through one helper, `_sync_active_index` (`selection.py:153-167`): it loops `items` and `setattr`s the index of the first whose `.name` matches the target. **The bug spec 043 is fixing lives exactly here:** `_sync_active_index` indexes against the *raw* collection order, but the UIList renders a *filtered, reordered* view via `flt_neworder`, so the highlight lands on the wrong row when a filter or sort is active (spec 043 finding F-06, `043-outliner-selection/STUDY.md:18,28`). Any list with a `filter_items` that reorders inherits this bug. The slot list will have a filter (slot-only + search), so it inherits it unless the shared component does the index mapping correctly. This is why the component's active-index sync must be **identity-based and filter-aware**, not a raw-collection position.

**The attachment list cannot bind to a collection as-is.** `empty.children` is a computed read-only sequence Blender derives from the parent pointers of every object — it is not a `CollectionProperty` on the Empty, so there is no `(data, propname)` pair to hand `template_list`, and there is no place to store a stable per-row order or an active index that survives re-parenting. `template_list` requires `data.propname` to be an actual registered collection. So the attachment list is the one place none of the three precedents directly applies.

**The mesh-attach flow is genuinely blocked by single selection.** `proscenio.add_slot_attachment` (`operators/slot/attachment.py:40-67`) re-parents *every selected MESH* into the active slot via `parent_keep_world`, and its `poll` requires the slot Empty to be active AND a non-slot mesh to be selected at the same time. With single-object selection you cannot have both the slot active and a target mesh selected, so the only path today is multi-select-then-activate gymnastics. A picker decouples target choice from the active object.

**The bone half is already done — do not rescope it.** The Bind to Bone work (#117/#118) shipped `proscenio.bind_slot_to_bone` (`operators/slot/bind.py:34-102`) with a real picker: `invoke` opens `invoke_props_dialog`, `draw` renders `prop_search(self, "bone_name", armature.data, "bones")`, and it seeds from the active pose bone or the existing `slot_bone`. Unbind is its pair (`bind.py:105-126`). The Active Slot panel already draws the Bind/Unbind button and the follow state (`slots.py:44-93, 173-176`). So "attach a bone to a slot" is a solved, shipped flow; this spec's picker is **mesh-only**, and must sit alongside (not replace) the bone Bind dialog.

**The redundant warning is a panel/validator duplication.** When a slot has no mesh children the panel draws `row.label(text="empty slot - add child meshes", icon="INFO")` (`slots.py:180-183`), and *separately* the validation loop at `slots.py:215-216` renders every issue from `validate_active_slot`, the first of which is `Issue("error", f"slot '{name}' has no MESH children", name)` (`core/validation/active_slot.py:28-29`). So an empty slot shows two near-identical messages, one INFO one ERROR. The validator's version is the load-bearing one (it carries severity and feeds Validation panel aggregation); the panel's inline INFO is the duplicate to drop. Note the validator early-returns on the no-children case (`active_slot.py:28`), so removing the panel line loses nothing the validator does not already say — except that the validator line is an error tint, which is arguably the right signal for "this slot will export nothing."

**No shared list helper exists yet.** `panels/_helpers.py` holds only header/affordance utilities — `draw_subpanel_header` (`:72-86`), `draw_subbox_header` (`:88-108`), `draw_picker_readout` (`:111-124`), `draw_issue_row` (`:127-150`), and the mode predicate sets. There is no list wrapper. The component lands here, next to the affordances every panel already imports from this module.

### Research notes

**`template_list` binds to a CollectionProperty, not a Python list.** Blender's `UILayout.template_list(listtype_name, list_id, dataptr, propname, active_dataptr, active_propname, ...)` requires `dataptr.propname` to be an actual collection (`bpy.data.objects`, `Armature.bones`, a registered `CollectionProperty`) and `active_dataptr.active_propname` to be an `IntProperty` index into it. It cannot be handed an arbitrary list computed at draw time; the collection must persist on a data-block so Blender can index, scroll, and store the active row across redraws. This is the hard constraint behind the attachment-list decision.

**Two real options for the dynamic attachment list:**

1. **A synced `CollectionProperty` of attachment entries on the slot Empty** (e.g. `proscenio.attachments` holding a `name` `StringProperty` per child mesh), rebuilt from `empty.children` whenever it drifts. Because Blender forbids writing properties during `draw`, the rebuild must run from a handler (`depsgraph_update_post`, mirroring the existing armature-sync handler spec 043 references at `043-outliner-selection/STUDY.md:19`) or lazily at the start of each relevant operator — never in `draw`. This buys real `template_list` behavior: native scroll, native name filter, a stored active row. The cost is a new property group, a sync function, the handler wiring, and a correctness burden (re-parents, deletes, undo, and the swap-keyframe index in `attachment.py:142` all have to keep the collection and `empty.children` in agreement). It also introduces a *second* index space (the swap keyframe already indexes by sorted child-name position) that must not diverge.

2. **A custom-draw list inside the shared component** — the component exposes a "draw your own rows over a Python sequence" mode (a `column` of rows with a fixed `rows=` height and a `scale_y` scroll-ish cap, or a `template_list` only for the collection-backed callers and a hand-rolled scrollable column for sequence-backed callers). This keeps the attachment data as today's derived `empty.children` view, costs no handler and no new property group, and cannot desync because there is nothing to sync. It does not get Blender's native scrollbar or filter field for free — those would have to be faked (a search `StringProperty` + manual substring filter, like the Outliner's pre-043 dual-search) or simply omitted for the attachment list.

The Outliner precedent (`outliner.py:86-124`) shows option 1's filtering is achievable, but the Outliner binds to an *already-existing* collection (`bpy.data.objects`); the attachment list has no such collection, which is the whole difficulty — option 1 means *creating and maintaining* one.

### Verdict summary

**Five rows land now, one (the synced-collection upgrade) gates.** The recommendation is **four PRs**, sequenced after spec 043's identity-based index fix lands (or sharing the same corrected `_sync_active_index`, since the slot list inherits the F-06 filter-reorder bug the moment it has a slot-only filter):

1. **The reusable component**, built into `panels/_helpers.py` with filter-aware identity-based active-index sync, plus a custom-draw mode for sequence-backed lists (so the attachment list and spec 044's override list can both adopt it). This is the structural keystone — the other near-term specs depend on it, so it ships first and alone.
2. **Migrate the project slot list** to the collection-backed path (slot-only filter over `scene.objects`, the Outliner pattern), with a new `active_slot_index` scene prop and `select_slot` writing it through the corrected sync.
3. **Migrate the attachment list** to the component's custom-draw mode (option 2 backing) with a bounded scroll height, preserving the default toggle / kind / keyframe affordances, and **remove the redundant empty-slot INFO line** in the same PR (both touch `slots.py` draw).
4. **The attach-mesh picker** — a `prop_search` mesh dialog on a new operator, with Add Selected Mesh kept as the already-selected fast path.

The synced-`CollectionProperty` upgrade (option 1) is written down as a gated follow-on, not built now: it earns its handler-and-undo complexity only when the attachment list needs a persisted active row, a native filter, or drag-reorder that the derived view cannot give.

**Dependencies.** Spec 043's identity-based index fix should land first or be shared — the slot list inherits its filter-reorder bug. Spec 044's override list adopts this component after PR 1 lands (spec 044 names this dependency explicitly at `044-weight-paint-mode-sync/STUDY.md:20`). The bone-attachment half is already shipped (#117/#118, `bind.py`) and is out of scope here.
