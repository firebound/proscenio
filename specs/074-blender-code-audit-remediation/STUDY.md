# Spec 074 STUDY: Blender code-audit remediation

## Why

The 2026-06-28 multi-agent structural audit ([backlog/code-audit/](../backlog/code-audit/)) catalogued architecture + correctness findings for `apps/blender/`. Its structural pass was adversarially verified, but the 40 correctness candidates in [bugs.md](../backlog/code-audit/bugs.md) were never verified (the run hit a token limit before the verifier stage). This spec finishes that verification and drives the fix of **everything that survives verification**, with a hard constraint: **no functionality is lost** - every change lands behind a green guard test (existing or newly added).

A 7-agent verification pass (2026-06-29, against HEAD) re-read every finding against the current code. Specs 069/070/071/073 shipped after the audit, so a handful are already fixed or stale. This STUDY records those verdicts and scopes the remainder.

## Verification outcome (what changed since the audit)

7 agents, one per theme, returned a per-finding verdict (VALID / FIXED / STALE / REFUTED) with the current `file:line`, a concrete behaviour-preserving fix, and the functionality guard.

- **Bugs (40 candidates):** ~34 VALID, 5 not actionable. Not actionable: `modal-guard-no-cancel` (FIXED by spec 070's `cancel()` hook), `degenerate-close-corrupt-state` (FIXED by spec 070's `VertexPen.close()` + island re-arm), `commit-contour-outer-not-manual` (STALE - the OUTER "contour" tool is dead code since spec 070), `driver-source-bone-enum-remap` (REFUTED - the 3-tuple's first element IS the bone-name id; the read path validates loudly), `slot-default-min-name` (VALID but benign - Godot resolves the default by name, so cosmetic only).
- **Structural (god-modules/SRP, misplaced, dependency-direction, duplication, dead-code, test-quality):** all confirmed VALID at HEAD except `authoring-ik-module` (REFUTED as a god-module: it is a single cohesive IK feature, four operators sharing helpers - a size-only smell, do not split by operator). The 6 phase-1 [refuted.md](../backlog/code-audit/refuted.md) items stay excluded.

Net: **~94 actionable items**, all low-to-medium except a cluster of high-severity correctness bugs (below). The audit's headline ("structurally healthy, slow-burn cleanup") holds - there is no critical structural defect - but the correctness pass surfaced real high-severity bugs the structural pass could not see.

## The high-severity correctness set (Phase 1 - fix first)

These are the only high-severity items; each is small/trivial effort and currently has **no guard**:

- **bone-frame0-negative-time** ([animations.py](../../apps/blender/exporters/godot/writer/animations.py) `collect_bone_keys`) - a bone action keyed at Blender frame 0 yields a negative `Key.time`, which trips the Pydantic `ge=0` constraint and **aborts the entire export**. The two peer writers already clamp with `max(0.0, ...)`; this one does not. One-line fix.
- **redo-wrong-parent** ([quick_armature.py](../../apps/blender/operators/armature/quick_armature.py) `_redo_last_bone`) - redo re-derives the parent from the live `_last_bone_name` instead of the record's stored parent; spec 069's reparent-by-selection makes the divergence readily reachable and it **silently corrupts the authored bone chain**.
- **keyframe-slot-index-drift** ([attachment.py](../../apps/blender/operators/slot/attachment.py) `keyframe_slot_attachment`) - the slot-swap keyframe stores a positional child index; adding/removing/reparenting a child shifts every later index, so an authored swap **silently resolves to the wrong mesh or is dropped**. The existing test pins the buggy positional contract and must be rewritten to bind by name.
- **finish-flag-clear-last** (both automesh modals' `_finish`) - `mark_stopped` runs after the cleanup steps inside the `try`; if any cleanup raises, the modal-exclusivity guard stays set forever, **permanently locking out both authoring modes** until addon reload. (Spec 070's `cancel()` covers external kill but not a raise inside `_finish`.)
- **regen-wipes-provenance** + **regen-drops-snapshots** ([automesh_hook.py](../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py)) - one shared root cause: the pre-regen snapshot rebuilds the sidecar with a flat `auto_seed` provenance and an empty `snapshots` list, so an automesh regen **discards painted-vs-auto provenance and every named/rolling weight snapshot** - even on an identical-topology no-op regen. The existing `test_automesh_regen.py` guard is too weak (it passes with the bug present).

## Decisions (locked, with rationale)

| # | Decision | Rationale |
| --- | --- | --- |
| D1 | **Fix everything VALID; exclude the 5 not-actionable bugs + the 7 refuted structural items.** | The intent is total remediation, but re-fixing already-fixed/dead/refuted findings is churn and risks regressions. The exclusions are evidence-backed (verified against HEAD). |
| D2 | **No functionality loss = guard-test-per-fix.** Where a finding has an existing guard, the fix keeps it green. Where it has **no guard** (most of them), the regression test is written first (test reproduces the bug -> fix makes it pass). | This is the only mechanical guarantee that "improve" does not become "break". The audit explicitly flagged the missing guards; the spec turns each into a test. |
| D3 | **Sequence by risk, not by theme: Phase 1 high-sev correctness -> Phase 2 medium correctness + the provenance cluster -> Phase 3 quick-win cleanups (dead-code, trivial inlines, DRY folds, misplaced-code moves) -> Phase 4 low-sev bugs + performance -> Phase 5 test-quality hardenings + the one medium (untested modal lifecycle) -> Phase 6 large refactors.** | High-sev correctness ships value first; the cheap mechanical cleanups are safe and fast; the breaking refactors come last and may be deferred. |
| D4 | **The whole god-modules / SRP decomposition theme moves to its own spec ([075-blender-structural-decomposition](../075-blender-structural-decomposition/STUDY.md)), actively worked - NOT gated.** The three large splits (`automesh_authoring.py` 1642 lines, `quick_armature.py` 1084, `ProscenioSkinningProps` breaking across 30 files) plus the ~14 smaller SRP extractions are real planned work there, not deferred-behind-a-trigger. This spec (074) keeps the correctness bugs, performance, dead-code, DRY folds, misplaced-pure-logic moves, dependency accessors, and test-quality. | The user's direction: do not gate the structural work, it needs doing. Splitting it into a focused decomposition spec keeps 074's bug/cleanup diffs reviewable and gives the higher-risk module surgery its own STUDY + phasing + guard discipline. Un-gates what spec 061 had deferred behind a trigger. |
| D5 | **Multiple PRs, phased; docs/spec prune happens after the final phase merges.** Each phase is an independently-reviewable, gates-green PR. | A single mega-PR over the item set is too large to review; phased PRs keep each diff small and easy to bisect, and let the high-sev fixes land immediately. |
| D6 | **Respect the verified justified divergences - unify only the genuinely-shared core.** Three DRY clusters (point-to-segment clamp policy, selection-mode-snapshot restore semantics, material-walk outer-iteration scope) have intentional differences; the shared helper must preserve both behaviours, and `selection-mode-snapshot-dup` needs a guard for the "active untouched when mode unchanged" semantic added *before* unifying. | Over-eager DRY would erase real behaviour - the exact failure mode the audit's adversarial pass guards against. |

## Open items (confirm during build)

- **O1 - RESOLVED:** the structural decomposition (god-modules + SRP) moves to [spec 075](../075-blender-structural-decomposition/STUDY.md), actively worked, not gated (D4).
- **O2 - RESOLVED: delete `psd_naming.py` + its test.** Verified pipeline: spritesheet frames are authored in Photoshop (a LayerSet tagged `[spritesheet]` -> `planner.ts` groups them -> the manifest carries an explicit `SpriteEntry.frames` list, [psd_manifest.py:91-109](../../packages/models/src/proscenio_models/psd_manifest.py#L91)) and Blender just consumes the manifest. The grouping lives in PS, by design; the Blender-side `psd_naming` "guess from layer names" is the wrong layer and never got wired (zero callers). Deleting it loses no feature. (Phase 6 item below.)
- **O3 - keyframe-slot-index-drift needs a binding-mechanism decision before coding.** The fix "bind by name not position" can be (a) a string Custom Property the writer reads, or (b) a stable per-slot attachment ordering keeping the integer fcurve. (a) touches the export round-trip + the existing test's contract; (b) is less invasive but needs an ordering source. Decide at the top of Phase 1's slot work - this is a real design fork, not a one-liner.
- **O4 - animated-delta-rest-rotation is heavier than a normal medium fix.** Correctly baking a child translation under an animated-rotating parent needs a per-frame posed-parent sample (scene-stepping, like `sprite_frame_animations._bake_track`), not a formula tweak. Decide: implement the per-frame bake (real effort), or ship the fast path + a documented limitation (skip when the parent has rotation fcurves). Confirm before Phase 2.
