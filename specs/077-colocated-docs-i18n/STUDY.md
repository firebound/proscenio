# Spec 077: Co-located multilingual docs source

Spec 072 shipped the pt-BR docs translation in Docusaurus's native `apps/docs/i18n/pt-BR/` tree - a directory that lives far from the English source under `docs/`. Editing one page means editing two files in two distant trees, and English is the implicit default (read straight from `docs/`) while every other language is a peer under `i18n/`. This spec restructures the docs *source* so every page's languages sit side by side under `docs/`, and demotes the Docusaurus `i18n/<locale>/` layout to a generated, gitignored build artifact the site consumes. English and Portuguese become symmetric language packs: no locale is special in the source.

This is a source-restructure spec, not a re-translate spec. The pt-BR copy that spec 072 landed is preserved verbatim - it just moves next to its English sibling. The engineering deliverable is: the co-located source layout, a Node sync tool that generates the Docusaurus i18n trees from it, the coverage guard, the config rework, and the one-time migration of the 31 existing page pairs plus chrome.

## Why now

- The maintainer read the shipped 072 layout and wants the languages co-located: "preciso que as documentações estejam lado a lado". Editing a distant mirror tree is the friction.
- The 072 docs are fresh (pruned 2026-07-04, PR #185) and the English/pt-BR page set is a clean 1:1 (31 pairs), so the migration is a mechanical move before the trees drift.
- The user set the guiding principle explicitly: English must be an equal language pack, not the implicit default - "en é default mas deve ser tratado como pacote de idioma igual".

## Current state

- Site app: [apps/docs/](../../apps/docs/); English content served straight from repo-root `docs/` (`path: '../../docs'`, `routeBasePath: '/'`) in [docusaurus.config.ts](../../apps/docs/docusaurus.config.ts).
- pt-BR lives in the Docusaurus i18n tree from spec 072:
  - `apps/docs/i18n/pt-BR/docusaurus-plugin-content-docs/current/**` - the 31 translated pages, mirroring `docs/` path-for-path.
  - `apps/docs/i18n/pt-BR/docusaurus-theme-classic/{navbar,footer}.json` - translated chrome.
  - `apps/docs/i18n/pt-BR/code.json` - Docusaurus's own theme-UI strings, translated.
  This tree is committed today.
- English content inventory under `docs/`:
  - **31 hand-authored pages**: `00-guides/**` (11), `01-project/**` (4), `02-tools/**` (13), `docs/README.md`. Each has a pt-BR counterpart in the i18n tree.
  - **10 auto-generated files**: `docs/content/**` (the proscenio + psd-manifest schema reference `.mdx` + `content/README.md`), emitted by `proscenio_codegen all`. Single-language, English-only (spec 072 D6). Never hand-edited.
  - **`docs/images/**`**: page assets referenced by relative path.
- English chrome is not a file today - it is the inline `label:` strings in [docusaurus.config.ts](../../apps/docs/docusaurus.config.ts) (navbar `Guides`/`Project`/`Tools`/`GitHub`, footer titles + labels, copyright) and the category labels in [sidebars.ts](../../apps/docs/sidebars.ts) (`Guides`, `Schema`, `Blender Addon`). That is the implicit-default asymmetry this spec removes.
- Doc ids / slugs strip the `NN-` numbered prefixes; `sidebars.ts` mixes `autogenerated` (dirName + numbered-prefix ordering) and explicit doc ids. The numbered prefixes are load-bearing for ordering and must survive the migration.
- Deploy: [.github/workflows/docs-deploy.yml](../../.github/workflows/docs-deploy.yml) is a Node/pnpm-only job (node 22, `pnpm build`), no Python runtime.

## Decisions

| # | Question | Call |
| --- | --- | --- |
| D1 | Source of truth | Co-located `docs/`. Every hand-authored page exists as `docs/<path>/<name>-<lang>.md` per language; the Docusaurus `i18n/<locale>/` trees are generated from it and gitignored. English stops being read from `docs/` directly - it becomes a generated pack like every other language, honoring the equal-pack principle. |
| D2 | Language suffix | Symmetric `-en` / `-pt` on the file stem (`index-en.md`, `01-photoshop-pt.md`); the `NN-` numbered prefixes stay on both directory and stem. Short language codes in the source; the sync maps them to Docusaurus locales (`en` -> `en`, `pt` -> `pt-BR`) via one table. Short symmetric suffixes read cleanly side by side; the BCP-47 `pt-BR` is a Docusaurus concern kept in the sync map, not smeared across 31 filenames. |
| D3 | Chrome source | The addon-controlled chrome (navbar item labels, footer titles + labels, sidebar category labels, copyright) lives co-located in `docs/_i18n/chrome-<lang>.json`, one per language, both explicit. The sync splits each into Docusaurus's `navbar.json` / `footer.json` / `current.json`. Docusaurus's own theme-UI strings (`code.json`, ~90 framework strings) are framework-provided: pt-BR carries the migrated `docs/_i18n/code-pt.json`, English uses Docusaurus defaults. That one asymmetry is invisible framework text, not product content. |
| D4 | Sync tool language | Node, not Python. `apps/docs/scripts/sync-i18n.mjs`, run as an npm `prebuild` / `prestart` lifecycle hook so `pnpm build` and `pnpm start` both regenerate, tested with the built-in `node --test` runner (zero new deps). The docs surface is a Node/pnpm world: a Node script runs inside the existing docs CI (node 22) with no new runtime, keeps local dev symmetric, and is self-contained under `apps/docs/` (scripts-co-located-per-package, [layout.md](../../.ai/conventions/layout.md)). The Blender i18n tooling is Python for the Python addon; the docs tooling is Node for the Node site. |
| D5 | Generated layout | The sync writes, for BOTH `en` and `pt-BR` symmetrically, `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/**` (prose with the `-<lang>` suffix stripped), the chrome JSON, and copies the single-language assets (`docs/content/**`, `docs/images/**`) into each locale tree so both locales serve the schema reference and images. `apps/docs/i18n/` is gitignored; the committed `i18n/pt-BR/` tree from spec 072 is removed. |
| D6 | Default-locale content path | Docusaurus reads the default locale's docs from the docs-plugin `path`, other locales from `i18n/<locale>/`. To keep English a peer under `i18n/`, point `docs.path` and the search `docsDir` at `./i18n/en/docusaurus-plugin-content-docs/current`. If a build shows Docusaurus double-processing that directory for the default locale, fall back to a neutral generated directory (`apps/docs/.i18n-build/en/`) for English content - the source stays symmetric either way. Verified at build (see Open calls). |
| D7 | Edit-this-page links | With the docs served from the generated tree, `editUrl` becomes a function that maps a generated doc path back to its co-located source `docs/<path>/<name>-<lang>.md` on GitHub, so "Edit this page" opens the real authored file, not the artifact. |
| D8 | Coverage guard | The sync fails the build when a co-located page is missing a language (an `-en` without its `-pt`, or vice-versa) or when a suffix-less `.md`/`.mdx` sits in a translated directory (an un-migrated file). `docs/content/**` and `docs/images/**` are exempt (single-language generated assets). This is the reverse-coverage equivalent of the Blender i18n drift guard: a new page or a dropped translation fails fast rather than shipping a silent English-only page under pt-BR. |
| D9 | Migration | One-time restructure: rename the 31 `docs/**/<name>.md` to `<name>-en.md`; move the 31 `i18n/pt-BR/.../current/**/<name>.md` to `docs/**/<name>-pt.md`; extract the chrome into `docs/_i18n/chrome-{en,pt}.json` + `code-pt.json`; `git rm -r apps/docs/i18n/pt-BR`; add `/apps/docs/i18n/` to `.gitignore`. `docs/content/**` and `docs/images/**` stay put, single-language, copied into both locale trees by the sync. |

## Open calls (confirm before / during TODO execution)

- **D6 default-locale-in-i18n verification** - the primary layout points `docs.path` into `i18n/en/.../current`. Docusaurus 3.10 reads doc files from whatever `path` names, so this is expected to work, but the default locale also consults `i18n/en/` for theme overrides; the build must confirm no double-processing. The fallback (a neutral `apps/docs/.i18n-build/en/` for English content) is a one-line config change and keeps the source symmetric. Resolved by running the build, not by discussion.
- **`code-en.json` for full chrome symmetry** - recommend not carrying one. English theme-UI text is Docusaurus's own default set (~90 strings like Next / Previous); a `code-en.json` would commit framework defaults as noise. The product chrome (`chrome-en.json`) is symmetric; the framework chrome is not, and that is invisible. Flag if the maintainer wants literal 1:1 file symmetry anyway.

## Out of scope / follow-ons

- **Localized schema-reference docs** - `docs/content/**` stays English-only, copied into both locale trees. A locale-aware codegen emit remains gated on real pt-BR demand for the schema pages (unchanged from spec 072 D6).
- **Third+ languages** - the structure supports them: add the `-<lang>` page files, a `docs/_i18n/chrome-<lang>.json`, and one row in the sync's language-to-locale map. No re-architecture.
- **The Blender addon i18n surface** - untouched. This spec is docs-only; the `core/i18n_locales/` tables and the `scripts/blender/extract_i18n.py` tooling from spec 072 stay as they are.
- **Machine-translation of new copy** - out of scope; the sync guards *presence* of both languages, not translation quality.
