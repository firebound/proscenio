# Spec 080: Element bone binding - TODO

Fix the discarded element rest transform (sprites render rotated/shifted under any bone whose rest is not identity; rigid meshes under a bone double-transform), then unify the binding authoring on the slot's constraint model with the raw bone parent as a power-user fallback. PR 1 is the correctness fix end to end (schema + exporter + Godot builders + fixtures); PR 2 is the authoring refactor and the binding-state simplification. Docs land direct on main.

## PR 1 - Rest-transform fidelity (the bug fix)

Schema / model:

- [x] `packages/models` `SpriteElement`: optional `position` [x, y] px, `rotation` rad, `scale` [sx, sy] - the element's absolute (skeleton-space) rest transform (D1), declared after `bone` (Bone field order). Defaults preserve the old identity-local parse for existing documents.
- [x] Regenerate via `python -m proscenio_codegen all` (JSON schema + TS + gd bindings; the schema-reference docs render live from the dumped schema).
- [x] `proscenio_sprite_element.gd`: regenerated by codegen; `_set_fields` carries the present/absent distinction the builder keys on.

Exporter (`apps/blender/exporters/godot/writer/sprites/`):

- [x] `sprite_element.py` + `core/godot_export_math.sprite_rest_transform`: emit the rest transform from the object's rest `matrix_world` - position through the XZ->XY screen mapping, rotation as the angle of the screen-projected local X axis (sign-cancelled so a flip_h mirror never reads as 180 degrees), scale as the screen-projected axis magnitudes. The screen projection zeroes the depth axis, so both quad authoring conventions (PSD local-XZ, hand-made local-XY stood up) read identically; the vertical basis is the longer of the two projected candidates. Position always emits; identity rotation/scale are omitted (the modulate pattern). Rides the export's existing rest-pose context.
- [x] `_compute_sprite_offset`: the world-projected gap is pulled back into the node's local frame (rotate by -rest rotation, divide by rest scale) so the node transform never applies to it twice (D3); byte-identical for the unrotated unit-scale case, spec 076 flip sign-cancel preserved.

Godot builders (`apps/godot/addons/proscenio/builders/`):

- [x] Shared parent-local helper (`sprite_attach_util.element_local_transform`): `local = parent_global_in_skeleton^-1 * element_rest` derived from live rest globals at build time - the `slot_builder.gd` formula generalized.
- [x] `sprite_builder.gd`: apply the document rest transform through the helper (correct under a Bone2D, a slot anchor, or the skeleton root).
- [x] `mesh_builder.gd`: RESOLVED AS NO-CHANGE (D2 revised) - the writer already bakes rigid bone-parented mesh vertices bone-local, so the identity local composes correctly; a clarifying comment landed instead of a cancel.

Fixtures / goldens / tests:

- [x] New fixture `packages/fixtures/bone_attach/` -> `examples/generated/bone_attach/`: a +Z bone (rest rotation -90, the poison shape) + a sprite REAL bone-parented keep-transform with all three dropped components (origin gap from the bone head, authored 0.35 rad rotation, pivot offset that must survive the pull-back). The rigid bone-routed mesh case turned out already-correct (D2 revised) and is pinned Godot-side instead.
- [x] Regenerated the 9 existing goldens + the new one (10/10 pass; diffs are exactly the 5 sprite `position` additions - mesh elements byte-identical). `_shared/export_proscenio.py` gained the same prefer-source-models shim as run_tests.py so a post-model-change regen cannot silently use the stale installed wheel.
- [x] Writer units (tests/writer/test_sprites.py): translation mapping, in-plane rotation read, both quad conventions produce the same scale, mirror-is-not-a-rotation, offset pull-back under rotation and under scale; 131 pass.
- [x] Godot headless: new `tests/test_sprite_rest_transform.gd` (20 checks) - document rest pose lands exactly under a rotated bone chain, legacy no-`position` document keeps identity-local, slot-routed sprite does not double-cancel, rigid bone-parented mesh keeps identity local. Existing importer / sprite-region / slot-anchor / builder-guards / golden-scenes all green.
- [x] Verified against the real `examples/authored/firebound_guy` export, headless in Godot: `char__fire` upright at (507.5, -451) (was lying at the bone head), `char__eye__eyeball` at its authored (35.8, -651.6) (the 29 px gap that made the iris pop out), `char__eye__eye_glow` upright - all parented under their Bone2D so the pose delta still animates them. No re-authoring needed (R3).

## PR 2 - Constraint-first binding + state simplification

Shared core (D6):

- [x] Pure resolution home `core/_shared/bone_follow_resolve.py` (constraint names + `follow_subtarget`, attribute-walk so the writer / validators / pure pytest share one precedence definition) + bpy-bound core `core/bpy_helpers/_shared/bone_follow.py` (bind / unbind keep-world / shape / stale check / `drop_bone_parent_keep_world`) parametrized by constraint name (`Proscenio Slot Follow` kept, `Proscenio Sprite Follow` new); the slot helper is a thin wrapper.
- [x] Bind computes the inverse from `bone.matrix_local` (rest), not `pose_bone.matrix` (D7); returns a posed flag the operators surface as a warning (the follower snaps to the rest-relative spot Godot reproduces).

Element authoring (D4 - sprites AND rigid meshes, one binding model):

- [x] `operators/sprite/bone_parent.py`: Bind authors object-parent + Child Of via the shared core; poll widened to any rigid element (sprite or unskinned mesh; skinned binds via weights, R5) and refuses when already following; Clear drops whichever shape is live keep-world; the "use a slot for a flat follow" caveat retired. The orphaned raw-parent helpers (`parent_to_bone_keep_world` etc.) were deleted - the raw parent is hand-authored only.
- [x] One-click `Convert to Constraint` (`proscenio.convert_element_follow`) upgrades a raw bone parent in place, keep-world (R3); panel `_draw_bone_attach` shows the three states.

Binding resolution (D4/D5):

- [x] `resolve_sprite_bone`: follow constraint > `parent_bone` > first vertex group; the mesh bone-local bake condition widened to constraint-bound rigid meshes (`is_rigid_bone_bound`).
- [x] `writer/slots.py` + `validation.slot_parent_bone`: constraint subtarget first; the legacy `slot_bone` field + `parent_bone` stay as read-fallbacks for pre-080 files.
- [x] `slot_bone` retired as authority: `_write_slot_bone`, the PG proxy in `properties/object_props.py`, and the CP write are gone; bind/unbind clear a legacy field so touched files converge; `slot_follow_shape` lost `field_inert` (the panel derives a "legacy field - exports, not following" hint instead) (D5).

Validation (D7/D8):

- [x] `checks/bone_follow.py`, wired into `validate_export`: double-drive warning (BONE parent + Proscenio follow on one object, D8), stale-follow warning (stored inverse times current rest world is not identity - no matrix inversion needed - D7), and a follows-missing-bone warning. Fix path is the existing operators (Clear / re-Bind), named in the messages.

Tests:

- [x] Operator tests retargeted + extended (constraint authoring, rest-inverse-on-posed-bone for element AND slot, convert, clear, rigid-mesh/skinned poll, no-field-written, legacy-field cleared on unbind, shape vocabulary without `field_inert`); writer precedence units (constraint / parent / vgroup, repurposed-name guard, slot field/parent fallbacks); validation check units (healthy / double-drive / stale / missing-bone / unbound). 1035 repo-root + 306 in-Blender.
- [x] Goldens byte-identical through the authoring swap (R4) - and the `bone_attach` fixture gained a `pin` sprite bound the constraint-first way, so the new canonical path is golden-pinned end-to-end (10/10).
