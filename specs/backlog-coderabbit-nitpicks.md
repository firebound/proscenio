# CodeRabbit nitpick backlog (closed-PR sweep)

Still-valid nitpicks and quick wins harvested from CodeRabbit (and `github-code-quality[bot]`) review comments on the 135 closed PRs, re-checked against current `main` on 2026-06-18.

Method: 73 of the 135 closed PRs carried bot review comments (inline findings plus the collapsible "Nitpick comments" / "Outside diff range comments" sections in the review bodies). Each candidate was validated against the live tree - the codebase moved heavily since most of these PRs (the `blender-addon/` to `apps/blender/` restructure, renames, rewrites), so the large majority of flagged items were already fixed or made obsolete and were dropped. Only items confirmed to still apply in current code are below, each with the originating PR, the current file path, and what was checked. Big refactors and design-decision items were excluded by scope - this is the small/cheap residue.

Most items have a natural per-domain home ([backlog-bugs-found.md](backlog-bugs-found.md), [backlog-blender-6.md](backlog-blender-6.md), [backlog-photoshop.md](backlog-photoshop.md), [backlog-docs.md](backlog-docs.md), [backlog-code-quality.md](backlog-code-quality.md)); the natural home is noted per item. Kept here as one report at request, so the whole sweep is reviewable before routing.

## Correctness and robustness

These change behavior or guard a real failure mode, not just cosmetics. Highest value of the sweep.

- **cdt-output-type-unfiltered-holes** `[bug]` - `apps/blender/core/bpy_helpers/automesh/cdt.py:175` builds `holes = list(holes_world)` unfiltered, then line 179 sets `output_type = 2` (CDT_INSIDE_WITH_HOLES) when the list is non-empty - but `_build_cdt_inputs` (lines 91-93) silently drops holes with fewer than 3 vertices, so CDT is configured with holes that inject no constraint edges. Fix: pre-filter at 175 (`holes = [h for h in (holes_world or []) if len(h) >= 3]`) and drop the now-redundant guard inside `_build_cdt_inputs`. From PR #53. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **driver-shortcut-bool-on-collection** `[bug]` - `apps/blender/panels/_draw_driver_shortcut.py:41` uses `bool(getattr(armature.data, "bones", None))`, which is `True` even for a zero-bone armature because the `bpy_prop_collection` is itself truthy; the button enables when it should not. Fix: `bones = getattr(armature.data, "bones", None); has_bones = bones is not None and len(bones) > 0`, matching the established pattern in `apps/blender/properties/_dynamic_items.py:59`. From PR #35. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **atlas-bare-use-nodes-blender6** `[bug]` - `apps/blender/panels/atlas.py:93` (`if not mat.use_nodes or ...`) and the identical `apps/blender/operators/atlas_pack/_paths.py:64` read the bare `.use_nodes` attribute, removed in Blender 6.0, so both raise `AttributeError` at runtime there. Fix: `getattr(mat, "use_nodes", True)` in both, matching `apps/blender/core/_shared/material_images.py:45`. From PR #101. Home: [backlog-blender-6.md](backlog-blender-6.md).
- **atlas-apply-manifest-no-error-handling** `[bug]` - `apps/blender/operators/atlas_pack/apply.py:64` calls `read_manifest(manifest_json)` with no try/except, so a malformed or truncated manifest surfaces a raw `json.JSONDecodeError`/`KeyError` traceback instead of a clean `report_error` + `CANCELLED`. Fix: wrap in `except (json.JSONDecodeError, KeyError, TypeError, ValueError)` and report-and-cancel (`report_error` already imported at line 16). From PR #35. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **sidecar-from-json-unwrapped-float** `[bug]` - `apps/blender/core/skinning/sidecar_schema.py:115-119` has `_entry_from_dict` doing bare `float(anchor_raw[0])`, `float(anchor_raw[1])`, `float(v)` while `from_json`'s docstring promises "Always raises ValueError on failure"; a non-numeric element raises a raw `TypeError`/`ValueError` that bypasses the normalized contract. Fix: wrap the conversions in `try/except (TypeError, ValueError)` re-raising a descriptive `ValueError`. From PR #56. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **sprites-zip-strict-false** `[bug]` - `apps/blender/exporters/godot/writer/sprites.py:216` pairs `iter_poly_vertices(poly)` with `iter_poly_loop_indices(poly)` under `zip(..., strict=False)`, so a malformed polygon with mismatched counts is silently truncated into wrong topology instead of failing early. Fix: `strict=True`. From PR #104. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **selection-action-no-referenceerror-guard** `[bug]` - `apps/blender/operators/selection.py:188-190` accesses `armature.animation_data` / `animation_data_create()` with no guard; if the picked armature was deleted before execute, the freed object raises `ReferenceError` as a raw stack trace. Fix: wrap in `except ReferenceError: report_warn(...); return {"CANCELLED"}`, matching `apps/blender/panels/skeleton.py:112`. From PR #123. Home: [backlog-bugs-found.md](backlog-bugs-found.md).
- **validator-mutable-list-on-frozen-dataclass** `[code]` - `packages/validator/src/proscenio_validator/_types.py` declares `Metrics.leak_records_sample` (line 61), `Invariants.failures` (69), `Invariants.warnings` (70) as `list[...]` on `frozen=True` dataclasses; `frozen` blocks reassignment but not `.append()`, so the "immutable report" contract leaks. Fix: switch to `tuple[...]` with `field(default_factory=tuple)` and pass tuples at the construction sites. From PR #80. Home: [backlog-code-quality.md](backlog-code-quality.md).

## Test gaps (weak or missing coverage)

Each is a test that passes today but cannot catch the regression it appears to cover, or a branch with no test at all. All are quick to add.

- **weight-reproject-test-identical-donors** `[test]` - `tests/skinning/test_weight_reproject.py:66` and `:95` give every donor `{"A": 1.0}`, so the nearest-pick fallback tests pass even if nearest-selection is broken (any donor returns the same weights). Fix: give donors distinct weight dicts, place the target nearer one, assert the returned weights match the nearest donor. From PR #60.
- **ts-emit-test-empty-dir-passes** `[test]` - `tests/codegen/test_ts_emit.py:44` iterates `PHOTOSHOP_BINDINGS_DIR.glob("*.ts")` as a live generator; an empty directory means the loop body never runs and the test passes validating nothing. Fix: materialize to a list and assert it is non-empty before the loop. From PR #83.
- **weight-diff-test-missing-gained-vert** `[test]` - `tests/skinning/test_weight_diff.py` covers the "vert missing in after" case but has no case for "vert missing in before" (gained by paint), which `diff_weights` handles via its second loop (`core/skinning/weight_diff.py:34-36`). Fix: add a case `before={1:1.0}, after={0:0.25,1:1.0}` asserting `diff_weights(before, after) == {0}`. From PR #57.
- **bone-collection-visibility-test-missing-3x** `[test]` - `tests/skinning/test_bone_collection_visibility.py` ends at line 70 with only `test_restore_4x_round_trip`; the 3.x fallback restore path (via `bone.hide`) has no symmetric test. Fix: add `test_restore_3x_round_trip` reusing the `_armature_3x` helper (line 41). From PR #57.
- **density-test-missing-boundary-point** `[test]` - `tests/automesh/test_density.py` `TestPointInPolygon` (lines 60-86) never asserts the documented "boundary = outside" contract; the implementation handles it (`core/automesh/density.py:87-91`) but a regression would go undetected. Fix: add `test_point_on_boundary_returns_false` with a point on an edge. From PR #51.
- **slot-anchor-test-missing-parent-assertion** `[test]` - `apps/godot/tests/test_slot_anchor.gd:77-85` checks only the slot's `global_position` against the skeleton origin; a regression that parents to the skeleton root instead of the intended `child` bone also yields a near-zero rest position, so the bone-follow contract can break while the test still passes. Fix: assert `slot.get_parent() == child_bone` before the position checks. From PR #130. Home: [backlog-godot-importer.md](backlog-godot-importer.md).

Fix: `disabled={busy}` / `disabled={!dirty}`. From PR #48. Home: [backlog-photoshop.md](backlog-photoshop.md).
- **photoshop-spurious-key-on-select** `[code]` - `apps/photoshop/src/panels/sections/tags/Row.tsx:156` (`key="kind"`) and `:167` (`key="blend"`) put `key` on standalone `<select>` elements not inside a `.map()`; React only uses `key` for sibling-list reconciliation, so these mislead. - **photoshop-stray-empty-jsx** `[code]` - `apps/photoshop/src/components/Accordion.tsx:45` carries a stray `{ }` left over from removing an `eslint-disable-next-line`; it renders nothing but pollutes the JSX. Fix: delete it. From PR #80. Home: [backlog-photoshop.md](backlog-photoshop.md).
- **outliner-double-negative-boolean** `[code]` - `apps/blender/core/outliner_view.py:71` returns `not (filter_text and filter_text not in ...)`, a double negative. Fix: `if filter_text: return filter_text in getattr(obj, "name", "").lower(); return True`. From PR #122.
- **ts-emit-extra-blank-line** `[code]` - `packages/codegen/src/proscenio_codegen/ts_emit.py:86` does `body.replace("/* eslint-disable */", "", 1)` without consuming the trailing newline, leaving a double blank line at the top of the emitted `.ts` (visible in `apps/photoshop/src/schema_bindings/proscenio.ts`). Fix: replace `"/* eslint-disable */\n"` (or `re.sub(r"/\* eslint-disable \*/\r?\n", "", body, count=1)`). From PR #83. Note: regenerated output, so re-run codegen after the fix.
- **quick-armature-test-untyped-classvar** `[code]` - `apps/blender/tests/operators/test_quick_armature_modal.py:45-46` annotates `_session_records` / `_redo_records` as bare `ClassVar[list]`. Fix: `ClassVar[list[Any]]` (or the concrete element type). From PR #108.
