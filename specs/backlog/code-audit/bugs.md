## Resource lifecycle (modal cleanup / draw handlers)

- **modal-guard-no-cancel** `[high sev / high conf]` - [draw_mesh_vertices.py:266](../../../apps/blender/operators/automesh/draw_mesh_vertices.py#L266), [automesh_authoring.py:1514](../../../apps/blender/operators/automesh/automesh_authoring.py#L1514) - neither spec-070 modal defines `cancel()`, yet both register in the module guard via `mark_running` on invoke and only clear it in `_finish`. External kill (file load, area/window close, addon reload, quit) calls `cancel()` not `modal()`, so `_finish` never runs and the guard name stays in `_active` forever - permanently blocking BOTH mutually-exclusive modes until addon reload; the statusbar handler and (automesh) event timer also leak. `quick_armature.py:576` implements `cancel()` precisely for this.
- **finish-flag-clear-last** `[high sev / high conf]` - [automesh_authoring.py:1514](../../../apps/blender/operators/automesh/automesh_authoring.py#L1514), [draw_mesh_vertices.py:266](../../../apps/blender/operators/automesh/draw_mesh_vertices.py#L266) - in both `_finish`, `mark_stopped` runs in the try block AFTER `unregister_overlay` (+ timer remove + statusbar remove). If `unregister_overlay` raises (stale handle after reload), the `finally` only does report/redraw, so `mark_stopped` is skipped and the guard stays True permanently. `edit_weights.py:154` wraps each cleanup in `suppress(RuntimeError)`; these do not. Fix: clear the guard first, or guard each cleanup step.
- **manual-draw-invoke-leak** `[medium / high]` - [draw_mesh_vertices.py:149](../../../apps/blender/operators/automesh/draw_mesh_vertices.py#L149) - invoke's except clause only reports + returns CANCELLED with NO cleanup. If `_append_statusbar()` raises after the overlay handler is registered, the GPU draw handler is never removed (draws against a dead operator); if failure lands after `mark_running`, the guard is stranded. `automesh_authoring.py:376` calls `_finish(cancel=True)` in its except - mirror that.
- **edit-weights-no-cancel** `[medium / medium]` - [edit_weights.py:154](../../../apps/blender/operators/skinning/edit_weights.py#L154) - relies entirely on its 0.2s TIMER + ESC to reach `_finish`, defines no `cancel()`. External teardown (file load, area close, reload) leaks the event timer (keeps waking a dead operator's WM), the provenance overlay handler, and the prepended statusbar callback. No cross-modal lockout, but resources dangle until reload. Fix: add `cancel()` calling `_finish(cancel=True)`.
- **register-overlay-partial-leak** `[medium / medium]` - [draw_mesh_vertices.py:149-156](../../../apps/blender/operators/automesh/draw_mesh_vertices.py#L149) - `register_manual_draw_overlay` does multiple `draw_handler_add` calls and only returns the populated dict at the end. If a later add raises, the partial dict is discarded and `self._handles` assignment never happens, orphaning the already-added handlers permanently (no handle to remove them).
- **refresh-overlay-partial-leak** `[medium / medium]` - [authoring_overlay.py:412-424](../../../apps/blender/core/bpy_helpers/automesh/authoring_overlay.py#L412) - `refresh_overlay` does `unregister_overlay(handles)` then `return register_overlay(...)`. If register raises partway, the new partial dict is never returned, so `self._handles` still points at the OLD (already-nulled) dict; the new handlers leak and `_finish` removes nothing.
- **no-orphan-sweep** `[medium / medium]` - [draw_mesh_vertices.py:308-316](../../../apps/blender/operators/automesh/draw_mesh_vertices.py#L308) - both authoring operators store handles on the instance (not a ClassVar) and their module `register`/`unregister` have no `_sweep_orphan_handlers` (cf. quick_armature.py:1036-1057). On addon reload while a modal is live, the per-instance handles are unreachable and the draw handlers leak with no recovery.
- **automesh-invoke-partial-leak** `[low / medium]` - [automesh_authoring.py:364-382](../../../apps/blender/operators/automesh/automesh_authoring.py#L364) - if `register_overlay` raises partway, `self._handles` keeps the initial all-None dict (also missing the `outer_preview` key), so the except's `_finish` -> `unregister_overlay` removes nothing and the partially-added handlers leak.

## Domain invariant: weight provenance

- **regen-wipes-provenance** `[high / high]` - [automesh_hook.py:73](../../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py#L73) - `_snapshot_from_existing_sidecar` calls `snapshot_sidecar(..., provenance="auto_seed")`, rebuilding the sidecar from live vgroup weights and stamping EVERY entry `auto_seed` - it never reads the prior per-vert provenance. So after bind -> Edit Weights (paint -> `user_paint`) -> Automesh regen, the snapshot fed to reproject is all `auto_seed`; `weight_reproject`'s user_paint-carry logic has no donor to resurrect and the white user_paint overlay regions all demote. Values survive (read from vgroups), provenance does not - violates the preserve half of invariant (a). The reproject carry logic is effectively dead on the regen path.
- **regen-drops-snapshots** `[high / high]` - [automesh_hook.py:159](../../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py#L159) - the regen path rebuilds the sidecar from scratch and never carries `snapshots` forward (default `[]`), on both the identical-topology branch (writes snapshot-less `prior_sidecar`) and the topology-changed branch. After bind -> save manual snapshot 'pose-A' -> paint -> Automesh regen (preserve ON, identical topology), `read_snapshots(obj)` returns `[]`: every named + rolling restore point is gone, Restore Weight Snapshot has nothing. Fires even when topology is UNCHANGED.
- **regen-rerig-false-preserve** `[medium / medium]` - [automesh_hook.py:177](../../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py#L177) - new sidecar's `vertex_group_names` come from the CURRENT picker armature's deform bones, while prior entries are keyed by OLD bone names. If the user swaps target rig between paint and regen, reproject blends old-named weights but `apply_sidecar` only creates groups for the new names and skips unmatched - mesh ends weightless while the report claims 'N reprojected / preserved'. Conflates regen-preserve (a) with re-rig-loses (c).
- **noop-regen-overwrites-provenance** `[medium / high]` - [automesh_hook.py:156](../../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py#L156) - identical-topology fast path does `apply_sidecar(obj, prior_sidecar)` and persists `prior_sidecar` verbatim - which was built `auto_seed`. So even a no-op regen (same alpha/params) round-trips to an all-auto_seed sidecar; subsequent Edit Weights sees prior paint as not-user_paint, and Reset-to-Last-Saved treats the auto_seed state as baseline. The common 'tweak slider + re-run' loop quietly erases the paint-vs-auto distinction.
- **vgroup-fallback-wipes-provenance** `[medium / high]` - [automesh_hook.py:87](../../../apps/blender/core/bpy_helpers/skinning/automesh_hook.py#L87) - `_snapshot_from_vgroups_fallback` stamps `auto_seed` whenever the stored sidecar is missing/corrupt/empty. Intended for the Ctrl+P mixed flow, but it also fires when a user HAS painted but the sidecar JSON got corrupted (partial write, hand-edited CP), permanently discarding painted provenance as 'never painted'.

## Domain invariant: coordinate / axis

- **bone-frame0-negative-time** `[high / high]` - [animations.py:80](../../../apps/blender/exporters/godot/writer/animations.py#L80) - `collect_bone_keys` computes `time = (frame-1)/fps` with NO lower clamp, while the sprite_frame and slot writers both wrap the identical base in `max(0.0, ...)` because `Key.time` is `Field(ge=0)`. A bone action whose first keyframe sits at Blender frame 0 yields negative time -> Pydantic ValidationError at `build_bone_track` -> aborts the ENTIRE export. Pure missing `max(0.0, ...)`.
- **animated-delta-rest-rotation** `[medium / medium]` - [animations.py:248](../../../apps/blender/exporters/godot/writer/animations.py#L248) - `_resolve_pose_entry` rotates a keyed bone-local translation into parent-local using the parent's STATIC rest rotation `R(-rest.parent_world_rot)`, but Godot re-applies the parent's LIVE rotation at runtime. When the parent bone is itself animated to rotate, a screen-space translation (e.g. vertical bob) gets dragged off-axis by the parent's animated rotation. Correct only for frames where the parent is at rest rotation.
- **bone-length-armature-scale** `[low / medium]` - [skeleton.py:113](../../../apps/blender/exporters/godot/writer/skeleton.py#L113) - head/tail projected through `armature_obj.matrix_world` (inherits object scale) but `length = bone.length * ppu` uses armature-LOCAL rest length (unscaled). With non-unit un-applied armature scale, Bone2D spacing scales but emitted length does not - bone bars mismatch joint spacing.
- **flipv-offset-double-count** `[low / low]` - [sprites.py:130](../../../apps/blender/exporters/godot/writer/sprites.py#L130) - `_derive_flips` reads `flip_v = obj.scale.y < 0`; `_compute_sprite_offset` pushes local_center through the same `matrix_world` (already containing the negative scale) while Godot applies flip_v to the texture independently. For an off-center pivot + negative-scale flip, the mirror is double-counted. Centered sprites unaffected.

- **tablet-pressure-resets-tracker** `[low / medium]` - [edit_weights.py:145-148](../../../apps/blender/operators/skinning/edit_weights.py#L145) - `modal()` treats MOUSEMOVE with `pressure < 1e-6` as end-of-stroke and calls `flip_touched_after_stroke`, which unconditionally clears `_snapshot`/`_active_group_name`. - **bind-diagnosis-index-crash** `[low / low]` - [bind_diagnosis.py:113-132](../../../apps/blender/core/skinning/bind_diagnosis.py#L113) - `diagnose_isolated_islands` sizes `parent = list(range(vert_count))` and indexes it with raw face member indices. ### psd import
- **feet-landing-ignores-origin-offset** `[medium / high]` - [__init__.py:306](../../../apps/blender/importers/photoshop/__init__.py#L306) - `_anchor_meshes_at_feet` computes `bottom = obj.location.z - half_h`, assuming location.z is the bbox center. - **feet-landing-name-over-tag** `[low / medium]` - [__init__.py:300](../../../apps/blender/importers/photoshop/__init__.py#L300) - the layer lookup tries `layer_by_name.get(obj.name)` first, falling back to the `proscenio_import_origin` tag - reverse of the authoritative ordering everywhere else (tag primary, name fallback). ### slot

## Performance

- **arc-length-resample-quadratic** `[medium / high]` - [geometry.py:132-138](../../../apps/blender/core/automesh/geometry.py#L132) - inside the per-sample loop, `accumulated = edge_index_start_distance(contour, edge_index)` re-walks edges 0..edge_index every advance, making resample O(N^2 + N*M) instead of O(N+M). Runs for outer + inner + every hole on each `_recompute_current_stage` (every slider drag) and at APPLY - tens of thousands of redundant hypot calls per drag frame on the UI thread. Fix: carry `accumulated += edge_length` incrementally. (Pairs with the `perimeter-length-dup` DRY cluster in [duplication.md](duplication.md).)
- **depsgraph-handler-linear-scans** `[medium / medium]` - [_handlers.py:102-175](../../../apps/blender/properties/_handlers.py#L102) - `on_depsgraph_update` fires every transform/frame change; when active != highlighted (common while dragging), `sync_outliner` + `sync_slots` each call `source_index_for_name(bpy.data.objects, ...)`, a full linear scan, twice per tick (plus the bone variant). O(objects) per tick on the event loop in a dozens-to-hundreds-object scene. Fix: cache a name->index dict, or key off object identity.
- **steiner-filter-quadratic** `[medium / high]` - [bridge.py:564-581](../../../apps/blender/core/bpy_helpers/automesh/bridge.py#L564) - `_compute_steiner_points` filters every interior point against all holes via `any(point_in_polygon(...))` then against the full boundary vert list, O(points * holes * hole_verts). For a dense mesh (thousands of candidates) this dominates build_automesh, fully re-run on each APPLY and in the preview. Fix: spatial index / bbox reject per hole.
- **read-alpha-grid-full-walk** `[medium / medium]` - [bridge.py:166-239](../../../apps/blender/core/bpy_helpers/automesh/bridge.py#L166) - `read_alpha_grid` materializes the full `list(image.pixels[:])` then `_max_alpha_in_block` does pure-Python pixel reads over every source pixel regardless of downscale - O(source_w*source_h). At downscale=1.0 a 2048x2048 sprite is ~16M Python-level reads on the UI thread, re-run on each outline/inner slider drag. Fix: cache the alpha grid per (image, downscale) across a modal session, or vectorize.
- **find-best-inner-rotation-quadratic** `[low / medium]` - [geometry.py:226-235](../../../apps/blender/core/automesh/geometry.py#L226) - double loop tries every rotation offset over all N vertex pairs, O(N^2). Docstring assumes N=32-64 but N is a user slider that can reach the hundreds (~65k float ops at N=256), run at APPLY and in the SIMPLE preview. Only triggers in annulus mode (margin > 0). Fix: O(N log N) circular cross-correlation or cap the search window.
