# Misplaced code

Pure logic trapped in bpy-bound modules (forcing tests through the slow in-Blender harness), or bpy access leaking into otherwise-pure layers. All verified against the real code. Severities are low; the recurring payoff is bpy-free unit-testability and matching the project's `core/*_math.py` / `core/` bpy-free convention.

See also the two refuted "misplaced" claims in [refuted.md](refuted.md) (`bone-modes-cp-io`, `validation-abspath-bpy`) - both are sanctioned conventions, not smells.

## Confirmed / adjusted

- **godot-writer-math** `[low/small]` `[confirmed]` - [skeleton.py:52](../../../apps/blender/exporters/godot/writer/skeleton.py#L52) - `world_to_godot_xy`/`godot_world_angle_from_dir`/`wrap_pi` are pure math (only `math` + `mathutils.Vector`) in a module that imports bpy at top, so importing the math forces a bpy mock, against the established `core/*_math.py` convention. Used by animations.py, sprites.py, and tested directly in tests/writer/test_skeleton.py. Fix: move the three to a bpy-free module (e.g. `core/godot_export_math.py`), re-import in the three call sites, keep public names so they stay simple re-exports.
- **atlas-manifest-parser** `[low/small]` `[confirmed]` - [atlas_manifest.py:1](../../../apps/blender/core/bpy_helpers/atlas/atlas_manifest.py) - `read_manifest` + `Placement` are a pure JSON parser (no bpy) mislocated under `bpy_helpers/atlas/`, leaving them untested; their only dependency `Rect` is a bpy-free core/atlas dataclass. Fix: move to `core/atlas/atlas_manifest.py`, update the single lazy import in apply.py:55, add a round-trip unit test. `write_manifest` stays in atlas_compose.py (that module needs bpy for compose).
- **object-props-setter-context** `[low/small]` `[confirmed]` - [object_props.py:244](../../../apps/blender/properties/object_props.py#L244) - `_set_y_draw_order` does order->Y placement math by reaching into `bpy.context` + a function-local `addon_prefs` import inside a PropertyGroup `set=` callback. Fix: extract `obj.location.y = order * spacing` into an `(obj, order, spacing)` helper near helpers.py:41. Caveat: `set=` has no context arg, so preference resolution via `bpy.context` is an inherent limitation - the realistic win is pushing the math out, not removing the context reach entirely.
- **weight-panel-sidecar-parse** `[low/trivial]` `[confirmed]` `[quick win]` - [weight_paint.py:444](../../../apps/blender/panels/weight_paint.py#L444) - `_sidecar_counts` re-parses the weight sidecar JSON inline (raw `json.loads` + untyped dict access) instead of the existing typed `from_json`/`read_snapshots` path. Fix: add `count_entries_by_provenance(obj)` in `core/bpy_helpers/skinning/sidecar_io.py` beside `read_snapshots`, export it, call from the panel, delete the inline block.
- **automesh-snap-math-dup** `[low/medium]` `[confirmed]` - [automesh_authoring.py:803](../../../apps/blender/operators/automesh/automesh_authoring.py#L803) - the KNIFE/fold/contour pen reimplements `VertexPen`'s snap/axis-lock/pick-radius math (`_apply_axis_lock` is character-for-character `VertexPen._apply_axis_lock`; `_snap_pen_click` reproduces `VertexPen._snap`) while ADD/REMOVE already delegate to the shared `VertexPen` - two live copies of the same closed-loop pen geometry. Fix: extract the pure geometry into shared free functions (or drive the open-stroke path through a `VertexPen` too) so both pens share one source of truth. (Cross-listed in [duplication.md](duplication.md).)
- **planes-placement-math** `[low/small]` `[adjusted]` - [planes.py:229](../../../apps/blender/importers/photoshop/planes.py#L229) - `_layer_placement`/`_Placement`/`_origin_for_kind` are pure coordinate math, but the module is bpy-bound at import, so their existing tests (test_sprite_origin.py) must run through the slow in-Blender harness. Correction to phase 1: the symbols ARE tested, just via the wrong harness. Fix: move them to `core/psd/placement.py` (bpy-free zone), re-import into planes.py, migrate the pure-math test cases to a repo-root `tests/psd` test; leave only the bpy-dependent `build_sprite` round-trip in Blender.
- **armature-overlay-geometry** `[low/small]` `[adjusted]` - [_overlay.py:90](../../../apps/blender/operators/armature/_overlay.py#L90) - correction to phase 1: `_resolve_parent_tail_world` is correctly bpy-bound and should stay; the genuinely-movable pure helpers are `_draw_axis_guideline`'s endpoint math and `_preview_color_for` (mode->color). Fix: move the axis-guideline endpoint computation + press-mode->color selection (and their constants) into `core/armature/quick_armature_math.py` for bpy-free coverage; leave the GL-drawing wrappers in `_overlay.py`.
