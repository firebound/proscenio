# Deferred work

Items with real value, sequenced for a second stage but not held behind a written trigger (those are in [gated.md](gated.md)). The difference from a gate: a deferred item is scheduled work waiting its turn, usually to ride a related change so its cost is shared, whereas a gate waits on a demand signal that may never come. Carved out during the 2026-06-11 reconciliation (the durable number-to-topic map is `index.md`). Companion homes: [dropped.md](dropped.md) (value below cost), [decisions.md](decisions.md) (locked calls).

- **sprite-appearance (blend-mode half)** - Emit the `proscenio_blend_mode` Custom Property onto elements and map it to a `CanvasItemMaterial` (add / multiply / subtract), downgrading screen / overlay to normal with a warning. Rides Wave-1: the value is already upstream (PSD manifest + `proscenio_blend_mode` stamp), but `CanvasItemMaterial` cannot express screen / overlay, so PSD parity needs a documented downgrade rather than a day-one ship. (The modulate / z_index / flip half shipped in #105.)
- **shrink-start-size** - Shrink-to-fit / configurable atlas start size (the `start_size=256` floor at `atlas_packer.py:65` is never passed and has no scene prop). Rides the next packer-touching PR to share the fixture regeneration: atlas waste is real only at fixture scale.
- **test-godot generic golden walk** - A generic walk over all eight goldens with broad sane-tree asserts (counts, kinds, weights, slots, tracks), plus an audit of the four hand-authored fixtures with no baked equivalent (`dummy`, `effect`, `skinned_dummy`, `slots_demo`). The drift fix + four focused regression guards landed (#127-#132, spec 047); the generic breadth rides the next test-godot touch, since a headless assert still cannot catch a visually-wrong-but-structurally-consistent export.
- **shared adaptation per tick** - Collapse the read paths into a SINGLE `adaptDocument` snapshot per tick feeding the tag tree, the export preview, and the active-layer consumers from one read. The async multiGet reader behind the DOM-walk fallback landed on both paths in spec 048, so the remaining redundancy is small; the single-snapshot refactor is React-hook timing only a real panel can validate, so it rides the next read-path touch. (The full IPC perf diagnosis lived in a deleted photoshop-performance backlog; recover from git history if needed.)
- **proscenio-models-wheel-staleness-gate** - The Blender addon bundles a built `proscenio_models` wheel (`apps/blender/wheels/`) and the writer imports its models from there, but nothing checks the wheel reproduces from the current `packages/models/` source, so a model shape change can ship with a stale wheel (the failure mode PR #104 hit). Add a staleness test mirroring the committed-match schema / Godot / TypeScript tests - build the wheel to a temp dir and compare extracted source or the dumped schema, not the archive bytes - under `tests/codegen/`, plus a `wheels/README.md` "When to bump" line for any `packages/models/` shape change. Rides the next schema-touching change (the storage-split spec 037 rebuilds the wheel anyway). (Moved from `backlog/code-quality.md` in the 2026-06-20 backlog-drain wave.)
